# 抓包助手（网页版）

基于 mitmproxy 的极简抓包工具：本地起一个服务，浏览器就是界面。
实时列表、关键字过滤高亮、token 自动提取、一键复制。

## 快速开始

1. 安装依赖（首次）

   ```bash
   pip install -r requirements.txt
   ```

2. 双击 `启动网页版.bat`，浏览器自动打开 `http://127.0.0.1:16824`
   （启动时会弹一次 UAC 窗口：点「是」→ 管理员模式，证书静默安装全程无弹窗；
     点「否」也能用，首次抓包会弹一次证书确认框，已自动置顶）

3. 顶部填过滤条件（三个都可选，AND 组合，全部留空 = 抓所有请求）：

   | 输入框 | 作用 | 例子 |
   |---|---|---|
   | URL 包含 | 只抓 URL 里有该关键字的请求 | `progress`、`/api/login` |
   | Header 包含 | 只抓带某个请求头的请求 | `Cookie`、`CSESSION` |
   | 内容包含 | 在请求体/响应体里搜关键字（token 常藏在这里） | `token`、`openid` |

4. 点「▶ 开始抓包」→ 自动安装证书 + 设置系统代理

5. 在手机模拟器/小程序/浏览器里操作目标页面，命中的请求实时出现在左侧列表

6. 点任意一条看详情：请求头 / 请求体 / 响应头 / 响应体，关键字黄色高亮，
   JSON 和表单体（k=v&k=v）自动识别并格式化排版，右上角「复制」可复制当前标签页内容

7. 底部「⭐ 提取结果」按 Header 关键字自动提取命中值（去重、最新 6 个），点「复制」即得

8. 用完点「⏻ 退出程序」（或直接关掉网页，10 秒后服务自动退出），系统代理自动恢复

## 界面功能速查

- **⏻ 退出程序**（右上角红色）：停止抓包、恢复网络、服务退出，一步到位
- **搜索框**：列表内二次过滤（路径/域名/命中关键字）
- **导出 JSON**：下载当前所有捕获记录
- **清空**：清空界面列表（历史仍在 logs 目录）
- **修复网络**（右上角红色）：紧急关闭系统代理
- **证书徽标**：显示证书状态，未安装时点击自动安装
- **使用指南**（右上角）：三步上手说明，首次启动自动弹出
- **高级设置 · 请求头修改**：配置「名称=值」，发出的请求自动注入/覆盖（如改 UA）
- **自动检测更新**：页脚显示当前版本，点「检查更新」手动检测；
  发现新版本时页面顶部弹出提示（可跳过该版本），点「前往下载」升级

## 端口说明

- 界面 `16824`、代理 `16823`（避开了 8080 等常用端口）
- 被占用时**自动向后顺延**，界面显示的地址和代理端口永远是实际值
- 停止后端口立即释放，可马上重新开始

```

├── web/index.html       # 界面

└── 强制关闭代理-断网修复.bat  # 兜底：手动恢复网络
```

## 退出逻辑（防断网核心）

工具的退出分两级，界面按钮有明确区分：

- **「■ 停止」**：只停抓包（引擎+代理），服务继续运行，可改条件再抓
- **「⏻ 退出程序」**（右上角红色）：停止抓包、恢复网络、服务进程退出，网页显示退出完成页

除此之外的所有关闭方式也都安全：

| 你做的操作 | 结果 |
|---|---|
| 关闭所有网页标签页 | **10 秒后服务自动退出**并恢复网络（心跳检测，刷新页面不会误触发） |
| Ctrl+C（服务窗口） | 优雅退出，恢复网络 |
| 直接点服务黑窗口的 X | Windows 强杀前有约 5 秒清理窗口，自动恢复代理；万一没来得及，下次启动自愈兜底 |

不怕断网的三重保险：退出时恢复的是**你开启代理前的原状**；残留代理下次启动自动清理（只清理本工具端口段 168xx，不误伤其他代理）；界面和 bat 里各有紧急「修复网络」按钮。

> 想关掉浏览器让服务在后台继续抓包（如挂机抓手机流量）：把 `config.ini` 的
> `AUTO_SHUTDOWN_WHEN_NO_BROWSER` 改为 `0`，用完记得手动点「退出程序」或 Ctrl+C。

## 断网保护（四层）

1. 正常退出（点停止 / Ctrl+C / 关服务窗口）→ 自动恢复系统代理
2. 恢复的是开启前的原状（原来手动配了代理就还原成原代理）
3. **异常退出自愈**：被任务管理器强杀、断电等留下残留代理时，下次启动自动检测并恢复
   （只清理指向本工具端口段 168xx 的代理，不误伤其他代理设置）
4. 兜底：界面「修复网络」按钮 / `强制关闭代理-断网修复.bat`

## 管理员权限

- **正常情况不需要管理员**：注册表写当前用户、证书装当前用户存储、监听高端口
- 启动时自动实测权限；若被组策略限制，界面顶部出现红色「权限异常，点击以管理员重启」，
  点击后自动弹 UAC 提权重启

## 设置与配置文件

界面上的设置（过滤条件、端口、两个开关、请求头修改）都会自动保存到 `config.ini`，下次打开自动恢复，一般无需手动编辑。

```ini
[Settings]
TARGET_URL=            # = 界面「URL 包含」
HEADER_KEY=            # = 界面「Header 包含」
BODY_KEY=              # = 界面「内容包含」
PROXY_PORT=16823
WEB_PORT=16824
ENABLE_SYSTEM_PROXY=1  # 0=开始抓包不改动系统代理（手动配代理场景）

[HeaderModify]
# 上行请求头修改，每行 HeaderName=HeaderValue，如：
# User-Agent=Mozilla/5.0 (iPhone; CPU iPhone OS 8_3 like Mac OS X)
```

## 常见问题

**抓不到请求？**
- 确认状态是「运行中」，且设备流量走系统代理
- 过滤条件太严会全部滤掉，先全部留空验证，再逐个加条件
- HTTPS 首次使用需证书：点顶部证书徽标安装，或访问 `http://mitm.it` 手动装

**打不开网页/断网？**
- 点界面右上角「修复网络」，或运行 `强制关闭代理-断网修复.bat`

**想抓手机的流量？**
- 手机和电脑连同一 WiFi，手机手动配置代理指向 `电脑IP:代理端口`
  （需 `config.ini` 设 `ENABLE_SYSTEM_PROXY=0`，且防火墙放行该端口）

**更多证书/网络排查**：见 `常见问题排查.txt`

## 注意事项

- 抓包数据含敏感信息（cookie、token），logs 与导出文件注意保密
- 只监听 127.0.0.1，局域网设备默认无法连接你的抓包服务
- 引擎只代理走系统代理的流量；证书绑定（SSL Pinning）的 App 抓不到
